## 1. 背景与动机

导师获得科研经费(有使用期限,到期必须用完),惯例做法是提前周转:学校财务系统发放劳务费给同学 → 同学上交大部分(留辛苦费)→ 汇集到课题组资金池。

**核心模型:收入 + 支出 → 维护总金额。**

边界(PRD §1.3):发钱走学校系统,本系统只做**收钱统计**与**资金台账**;不做发放、不做模板下发、不自动算税。

## 2. 行为需求

### 2.1 角色与权限

- 仅 `admin`(经费负责人)与 `supervisor`(导师)可访问本模块;`student` 不可见(403);
- 权限判断在 service 层统一校验角色。

### 2.2 批次(M1)

- 新建批次:名称(如 "2026-08")必填,备注可选;创建者即经手人;
- 批次列表:按创建时间倒序,含汇总(明细数/应交总额/已交总额/未交总额);
- 批次状态:`active`(进行中)/ `done`(已完成,归档);
- 批次完成(M5):全部明细"已交清"才允许标记 done;未交清时返回错误并列出未交数;
- 批次删除:仅 active 可删;已 done 不可删。

### 2.3 明细录入(M2,两种方式)

**方式 A:手动逐条键入**
- 字段:姓名/学号/日期/应发/扣税/辛苦费/备注;
- `应交 = 应发 − 辛苦费`(**扣税不减**,扣税仅记录),自动计算,可手动覆盖;
- 姓名+学号命中历史 `participants` 则复用该 participant(历史账单关联)。

**方式 B:导入 Excel(.xlsx)**
- 可先下载**模板**(GET /api/finance/import-template,含表头);
- 上传 xlsx → 解析 → 校验 → **返回预览**(有效行/错误行/姓名+学号查重提示)→ 用户确认 → 批量生成明细;
- 导入列(表头识别,顺序无关):`姓名 / 学号 / 日期 / 应发 / 扣税 / 辛苦费 / 备注`;
- 应交由系统按公式计算(导入不含应交列);
- **日期兼容 `2026-08-22` 与 `2026/8/22` 两种格式**,自动归一化为 `YYYY-MM-DD` 存储,API 统一返回纯日期;
- 错误行(缺字段/金额非法/学号缺失/日期格式错)不入库,预览中列出。

### 2.4 上交登记(M3)

- 选某明细 → 填本次上交金额/日期/备注 → 生成一条上交记录;
- `item.returned += amount`;未交 = 应交 − 已交(自动);
- **资金池自动 +amount**(同一事务,关联该明细);
- 上交金额 > 未交余额 → 400;上交次数不限制(补交通常一次)。

### 2.5 资金池(M6/M7/M9)

- 单账户(预置"课题组经费账户");
- **收入**:上交/补交(自动入账)、导师补充(手动加数字,收入类型);
- **支出**:资金使用(如给师兄弟发劳务),手动登记(金额/日期/备注);
- 余额 = Σ收入 − Σ支出,实时计算;
- 流水列表:时间倒序,含类型/金额/类别/备注/经手人。

### 2.6 批次汇总(M4)

- 批次详情返回:明细列表(含每行应交/已交/未交)+ 汇总(发放总额/应交/已交/未交)+ 未交名单。

### 2.7 参与同学库(M8)

- 姓名+学号去重名单(含参与次数/累计应交/累计已交);
- 点击查看某同学跨批次历史账单。

## 3. 接口

契约 §F10(见 api-contract.md):

- `POST /api/finance/batches`(新建批次)
- `GET /api/finance/batches`(批次列表)
- `GET /api/finance/batches/:id`(批次详情 + 汇总 + 明细)
- `DELETE /api/finance/batches/:id`(删除 active 批次)
- `POST /api/finance/batches/:id/complete`(标记完成)
- `POST /api/finance/batches/:id/items`(手动加明细)
- `POST /api/finance/batches/:id/items/import-preview`(上传 xlsx 解析预览)
- `POST /api/finance/imports/:preview_id/confirm`(确认导入)
- `POST /api/finance/items/:id/submit`(上交登记)
- `GET /api/finance/ledger`(资金池余额 + 流水)
- `POST /api/finance/ledger/income`(导师补充)
- `POST /api/finance/ledger/expense`(资金支出)
- `GET /api/finance/participants`(参与同学库)
- `GET /api/finance/participants/:id/bills`(历史账单)

## 4. 验收标准(可测清单)

- [ ] student 访问任意 finance 端点 → 403;未登录 → 401
- [ ] admin/supervisor 可访问全部端点
- [ ] 新建批次:名称空 → 400;成功 → 201 含 id/状态 active
- [ ] 批次列表:倒序;含汇总字段
- [ ] 手动加明细:应交自动 = 应发−辛苦费(扣税不减);覆盖值生效;姓名+学号重复 → 复用 participant
- [ ] 缺字段(姓名/学号/日期/应发)→ 400
- [ ] 上交:金额 > 未交 → 400;成功 → returned 增加、未交减少、资金池 +amount、生成流水
- [ ] 多次上交(补交)→ 累计正确;交清后未交 = 0
- [ ] 批次完成:未交清 → 400(列出未交数);全交清 → 200 状态 done
- [ ] 删除:done 批次 → 400;active → 204(级联删明细/上交记录)
- [ ] 导入预览:上传合法 xlsx → 200 返回有效行/错误行/查重提示
- [ ] 导入确认:按 preview_id 生效;错误行不入库
- [ ] 导师补充/支出:余额相应增减,流水记录正确
- [ ] 资金池余额 = Σ收入 − Σ支出(多笔后仍一致)
- [ ] 参与同学库:去重;历史账单跨批次正确

## 5. 边界与异常

- **金额**:一律"分"(int64)存储,展示转元;负数/超长 → 400;
- **日期**:YYYY-MM-DD 校验;
- **事务**:上交 + 资金池入账同事务;导入确认批量同事务(部分失败全回滚);
- **Excel**:仅 .xlsx;空文件/坏文件 → 400;超大行数(>500)截断提示;
- **导入预览过期**:preview_id 不存在/超时(TTL 30 分钟)→ 404;
- **并发**:同一明细同时上交,以事务保证不超扣(未交校验在事务内);
- **participant 唯一**:`(name, student_no)` 唯一约束,冲突时复用;
- 已 done 批次不可再上交/加明细(400)。
